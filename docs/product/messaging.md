# Messaging

## Category

**AI execution optimizer**

This is the clearest working category. It describes the value without reducing
Landing to agent orchestration, model routing, or subscription management.

## Tagline

**The AI execution optimizer.**

## One-sentence description

Landing optimizes AI work by preserving the prompted perspective a task needs
while selecting an eligible execution path across models, providers, and agent
harnesses.

## Supporting language

Short expression:

**Plans. Delegates. Routes.**

More technical expression:

**An availability-aware execution layer for AI work.**

Outcome-oriented expression:

**Automatically select the best execution path for each task based on quality,
latency, cost, and availability.**

## Messaging principles

- Lead with execution optimization and the outcome it creates.
- Explain personas as reusable prompted perspectives, not as a fixed set of
  product-defined roles.
- Treat availability as a broad system property, not a synonym for a consumer
  plan limit.
- Use single-provider examples when explaining capacity buckets; the product has
  real value before cross-provider routing enters the story.
- Describe cross-provider support truthfully, but do not make consumer-plan
  pooling the product's identity.
- Use `harness` in technical material when it is precise. Do not depend on it as
  the primary public category.
- Prefer `optimizer`, `execution layer`, `scheduler`, or `policy engine` over the
  noisier and less differentiated `agent orchestrator` category.
- Describe meetings as an optional workflow that surfaces disagreement,
  tradeoffs, and minority concerns. Do not promise consensus.

## Language to avoid

Do not lead with claims such as:

- “Pool all your AI subscriptions.”
- “Never hit a usage limit again.”
- “Turn consumer plans into shared capacity.”
- “Bypass provider limits.”

Those claims make a secondary mechanism sound like the product's purpose and can
imply a use providers may not intend to support. Clean wording is not a legal
workaround: product behavior, distribution, documentation, and marketing must all
tell the same truthful story.

If a third party describes Landing as subscription pooling, do not adopt or
amplify that framing. Explain the broader execution-optimization purpose and the
supported integration model.

## Positioning test

The preferred message should make engineers understand the mechanism, make users
feel the relief of not choosing a model for every task, show that a useful
persona can survive a route change, and remain useful if provider policies or
pricing models change.
